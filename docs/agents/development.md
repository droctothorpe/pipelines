# Development and deployment

Use Python 3.11+ and the Node/npm pins in `frontend/.nvmrc` and `package.json`.
`uv sync --frozen --extra test --extra lint --extra codegen` sets up the SDK.
The only Python workspace distribution is `sdk/python` (`kfp`).

The native stack is generated by `samples/argo-native/deploy.py` using
`third_party/argo/VERSION`. It uses Argo, persistent PostgreSQL/archive and S3
artifact storage, and a static Nginx UI/proxy. See the sample README for commands.
The local setup uses development storage credentials and an internal self-signed
Argo certificate; bind port-forwards to loopback, not a public interface.

`_KFP_RUNTIME=true` selects lightweight in-container imports. The compiler embeds
the native bridge, preserving ordinary component images and their SDK installation
commands; unmodified PyPI KFP executors are part of compatibility validation.
`Compiler(image_digests=...)` emits content-named local references;
`compile_demo.py` creates and verifies their Docker tags.

Artifact-list consumers use an init-container and Argo's installed downloader.
SDK/UI submission resolves namespace artifact-repository configuration and mounts
Secret references only into that staging container. Keep its private executor
volume separate from Argo's shared bootstrap volume. Large-template offload needs
the controller's namespace-scoped ConfigMap-create Role; component service accounts
retain only their existing task-result permissions. See the staging evidence and
remaining limits in [SDK compatibility](../sdk-compatibility.md).

Frontend development proxies `/argo/`, `/kubernetes/` and `/config.json` to the
deployed authenticated proxy (default `http://127.0.0.1:3003`, override
`KFP_NATIVE_PROXY`). It does not run a Node application backend or manufacture
credentials. Use explicit Kubernetes contexts and restart a port-forward after
replacing its target UI pod.

The UI proxy has three authentication modes, selected by `deploy.py --auth-mode`
and the `KFP_UI_AUTH_MODE` container variable. `token` (default, used by CI and the
deployment smoke) forwards the browser's bearer token. `single-user` lets the
proxy's own editor-bound service account authenticate every request through an njs
helper and advertises itself at `/config.json`, so the UI never asks for a token.
Those two publish the deployment namespace there (`KFP_UI_NAMESPACE` from the
downward API); the UI uses it when the URL has no `?namespace=`. Keep single-user
mode for disposable local namespaces. `multi-user` is the Kubeflow platform mode:
Argo runs cluster-wide, the proxy trusts the identity header the authenticating
gateway sets (`KFP_UI_USERID_HEADER`, default `kubeflow-userid`), runs a
SubjectAccessReview for that user on every proxied request (`ui-proxy.js`
`authorize`, paths it does not know are refused) and then acts with its own
cluster-scoped account. The UI is also served under `/pipeline/` for the central
dashboard, which names the namespace over postMessage (`src/lib/Dashboard.ts`).
Tenant namespaces get `deploy.py --tenant`; people get access through the
aggregated `kfp-native-edit`/`kfp-native-view` ClusterRoles. See
[samples/argo-native/README.md](../../samples/argo-native/README.md).
